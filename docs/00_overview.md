## 決定事項(実装者は変更しないこと)

1. **モノレポ構成は既存スキャフォールドを踏襲**(npm workspaces: `server`, `client`)。既存 JS は TS に置き換える。
2. **DB は SQLite(Node 組み込み `node:sqlite` の `DatabaseSync`)**。ネイティブビルド不要。Node >= 22.13 を要求。DB ファイルは `data/novel-backup.db`(`.gitignore` 済み)。
3. **認証はサーバーセッション + httpOnly Cookie**。パスワードは `bcryptjs`。JWT は使わない。
4. **ロール**:`admin` は `viewer` の全機能 + 管理機能。初回起動時はユーザー 0 件なので `/setup` 画面で最初の admin を作成。
5. **作品データ(バックアップ)は全ユーザー共有、ブックマークはユーザー毎**。バックアップ対象 =「いずれかのユーザーがブックマークしている作品」。
6. **ライブ閲覧は 2 モード**
   - **ブラウズモード**:HTML 書き換え Proxy (`/proxy/<site>/...`) を iframe 表示。検索・ランキング等サイト全体を回遊できる。スクリプトは除去。
   - **リーダーモード**:サイトアダプタで本文をパースし、アプリ独自 UI で表示(スマホ/PWA 向け)。
   - ブラウズ中に作品ページ/話ページを開くと「ブックマーク」「リーダーで開く」ボタンが出る。
7. **サイト固有処理は `SiteAdapter` に閉じ込める**。ライブのリーダーモードとバックアップは同じアダプタを使う。
8. **バージョン管理は話(エピソード)単位**。本文ハッシュが変わった時だけ新バージョンを追加。削除された話・削除された作品もデータは消さずフラグを立てる。
9. **サイトへの負荷配慮**:ホスト毎に直列化 + 最小リクエスト間隔(既定 1500ms)、差分取得(更新日時が変わった話だけ本文取得)。
10. UI 文言は日本語。

## 非目標

- 各サイトのアカウント連携・サイト側ブックマークの同期
- 取得データの再配布・公開機能(個人利用前提。外部公開する場合も必ずログイン必須)
- R18 系サブドメイン(ノクターン等)への対応は初期スコープ外(アダプタ追加で拡張可能な設計にしておく)
